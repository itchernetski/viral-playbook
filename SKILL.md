# viral-playbook — плейбук виральности, удержания и монтажа

Скилл = знание + процедура.

- `PLAYBOOK.md` — универсальная анатомия контента: дистрибуция, психология, хуки, удержание, триггеры, форматы, сценарии, аналитика, чеклисты.
- `references/editing.md` — монтаж снятого видео: съёмка под монтаж, склейки, хук-монтаж, перебивки, субтитры, звук, цвет, экспорт, инструменты.
- `references/video-production.md` — продакшн роликов без лица (запись экрана, моушн-графика, видео из кода): порядок шагов, озвучка, промпт для звука.
- `references/video-tools.md` — инструменты со ссылками и лицензиями.
- `references/project-cards.md` — шаблон карточки проекта (голос, аудитория, боли, запреты) и пример.

## Когда вызывать

- Любая задача «сделать единицу контента»: рилс, shorts, TikTok, YouTube-ролик, карусель, пост, тред, рассылка, лонгрид, обложка.
- Монтаж: «как смонтировать», «нарезать», «сделать динамичнее», «субтитры», «звук к ролику».
- Разбор своего или чужого контента: «почему залетело / не залетело».
- Генерация идей, хуков, контент-плана, серий.

Не для: SEO-текстов под поиск, лендингов, редактуры готового текста по стилю.

## Процедура

### 0. Загрузить контекст (всегда)

1. Прочитать `PLAYBOOK.md` целиком — один раз за сессию.
2. Найти карточку проекта в `references/project-cards.md`. Если карточки нет — задать пользователю до пяти вопросов из конца файла, заполнить карточку по шаблону и дописать её в файл.
3. Если задача про монтаж снятого видео — прочитать `references/editing.md`. Про ролик без лица — `references/video-production.md`.
4. Если задача упирается в свежие тренды, звуки или изменения алгоритмов — один веб-поиск. Принципы из плейбука не устаревают, конкретные цифры платформ — да.

### 1. Определить задачу → ветка

| Запрос | Ветка | Выход |
|---|---|---|
| «Идеи / контент-план / о чём снимать» | **Ideation** | 10–20 идей в формате «боль → обещание → формат → хук», сгруппированы по триггерам |
| «Напиши сценарий / хуки / текст» | **Script** | Сценарий по шаблону §9 плейбука: хук в 3 слоях, тайминг, текст на экране, подпись |
| «Как смонтировать / нарежь / сделай динамичнее» | **Edit** | План монтажа по `editing.md`: список склеек с таймкодами, перебивки, субтитры, звук, настройки экспорта. Если есть файлы и ffmpeg — черновая сборка |
| «Разбери ролик / пост / почему не зашло» | **Autopsy** | Разбор по анатомии §3 + диагноз по таблице §12 + 3 конкретных правки |
| «Адаптируй под другой формат / платформу» | **Repurpose** | Матрица §8: одна идея → рилс / карусель / пост / тред / письмо, переписанные под носитель |
| «Серия / рубрика / формат канала» | **Series** | Шаблон: название, структура выпуска, 10 первых тем, крючок на подписку |

### 2. Делать, а не спрашивать

- Не задавать уточняющих вопросов, если карточка проекта заполнена. Давать несколько вариантов: хуков — 10, сценариев — 2–3.
- Каждый хук проверять по чеклисту §4.6 плейбука, каждый сценарий — по чеклисту §14.
- Каждую идею тегировать главным триггером: `[SAVE]`, `[SHARE]`, `[COMMENT]`, `[REWATCH]`, `[FOLLOW]`. Одна единица — один главный триггер.
- Писать на языке аудитории из карточки.

### 3. Передать в производство (если есть чем)

Проверить, какие скиллы и инструменты установлены у пользователя. Если подходящего нет — отдать результат текстом, готовым к ручной работе.

- Видео из кода (моушн, запись экрана) → скилл рендера видео (например HyperFrames или Remotion), если установлен. Вход: сценарий §9.1 + обязательный treatment-блок §9.5.
- Снятое видео → план монтажа по `editing.md`; если есть исходники и ffmpeg — черновая сборка по рецептам оттуда.
- После каждого рендера — проверка §14.5 (поиск зависших кадров + лист кадров).
- Карусель → скилл каруселей, если есть. Иначе — текст слайдов: слайд 1 = хук, слайд 2 = re-hook, последний = CTA + петля.
- Публикация — только после явного подтверждения пользователя.

### 4. После публикации (если пользователь приносит метрики)

Снять: охват, удержание по секундам (или % досмотров), сохранения, пересылки, комментарии, подписки. Применить таблицу диагностики §12. Выход: что переснять или перемонтировать, какой хук протестировать следующим.

## Форматы ответа

- **Хуки** — нумерованный список: тип хука (из §4), текст, что на экране в 0–1 с, почему работает (одна строка).
- **Сценарий** — таблица `сек | кадр/визуал | голос | текст на экране` + подпись (первая строка отдельно) + CTA + ожидаемый главный триггер.
- **План монтажа** — таблица `таймкод исходника | что оставить/вырезать | приём (склейка, зум, перебивка) | текст/звук`.
- **Разбор** — таблица `элемент | что сделано | оценка | правка`.
- Коротко. Без вступлений. Шаблон > описание.
